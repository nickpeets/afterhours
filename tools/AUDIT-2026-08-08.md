## BREAKS-SHOW

### F1 — A host reload ends the show for everyone

- **Repro (harness-confirmed):** live engine room mid-round; host reloads
  the page.  On boot the room's `status` flips to `ended`; every client
  gets `roomEndedUnderUs` → `beatAlone`/exit.  Observed directly: room
  `status:"ended"` after `page.reload()` on the host client.
- **What should happen (SPEC / Q1):** the show survives a reload.  True
  absence is already defined elsewhere: watchers exit after 80s without
  the host (`index.html:2733–2740`), and the zombie janitor ends rooms
  with no `host_seen_at` beat for 120s (`index.html:1948–1957`).
- **Root cause:** the boot-time crash-recovery block ends EVERY live room
  the user hosts, unconditionally — no staleness check:
  `index.html:1810–1815` (`for(const r of mine) end_show(r.id, null)`).
  "Your show doesn't outlive your presence" — but a reload IS presence.
- **Fix direction:** crash recovery honors the existing 120s absence rule
  (skip rooms with a fresh `host_seen_at`), letting a reloading host land
  back in her own live room.
- Severity: **BREAKS-SHOW** — one accidental Safari refresh on the host's
  phone kills the night for the whole cast.

### F2 — Ask state lives only in the host's window (finding C root cause)

- **Repro (harness-confirmed):** host asks u_s1 in the choosing window.
  Host's client: `#rt_seat0.is-asked` = true.  A spectator client in the
  same room: `is-asked` = false, `window.__ASKED_THIS_ROUND` = null.  The
  double's `room_events` for the room: **no event of any kind recorded for
  the ask.**  After a host reload the maps are gone (fresh page = empty
  maps; `leaveRoom` also wipes them, `index.html:4001`).
- **What should happen (SPEC / Q4):** ASKED is "visible to the whole
  room" (the code's own CSS comment, `index.html:416`) and must survive a
  host reload — rotation legibility is the point.
- **Root cause:** `askMark()` writes `window.__ASKED_THIS_ROUND/_SHOW`
  (`index.html:2135–2143`) — client-local memory.  Nothing ever writes the
  ask to the server (`ask_question` in the double records no event,
  `tools/lib/backend-double.js:238–242`; prod-side unknown but the client
  never reads one back either), and nothing reconstructs the maps from
  `room_events` on entry (`loadEventHistory` seeds hearts only,
  `index.html:3523–3535`).  fix/ask-truth (#7) fixed the KEYING
  ((member, round), one write, one gate) but not the SOURCE — the mark
  never leaves the host's window.  This is why the overlay "still doesn't
  work so well": on every screen except the host's it has never rendered
  at all, and the host's own copy dies on reload.
- **Fix direction:** make the ask a server fact — `ask_question` writes a
  `spotlight` room_event (double parity included); every client folds
  events → asked maps on entry and via the existing `handleEvent`
  `"spotlight"` case, so all roles render the same truth and reload
  restores it.
- Severity: **BREAKS-SHOW** — the rotation ("everyone gets a fair shot",
  owner rule Aug 7) silently breaks: after any host reload the house pick
  re-asks chair 1; the room can watch a man get two questions while
  another gets none, with no visible explanation.

### F3 — PASS viability is checked once, against the bench only (finding B)

- **Repro (harness-confirmed):** deciding phase, 3 chairs, 1 benched, card
  open, PASS visible.  (1) The only bench member leaves → PASS **still
  visible** (click-time belt catches it — card survives, no action — but
  the display lies until clicked).  (2) Chairs leave until ONE remains,
  bench 0 → PASS **still offered**; the belt (`index.html:3055–3058`)
  checks `roomCounts().bench<1` only — nothing checks the seated count, so
  passing the last chair (bench 0 via any refill) can leave an empty
  stage with no explicit ending.
- **What should happen (SPEC prime invariant / Q3):** PASS is offered iff
  the pass leaves a continuable show, and the predicate re-evaluates on
  EVERY roster change, not at card-open time.
- **Root cause:** the decide card's contents are computed exactly once, at
  phase entry, inside `egApply`'s deciding branch (`index.html:2918–2930`),
  and `egApply` short-circuits when phase+deadline are unchanged
  (`index.html:2900`) — roster events go to `loadRoomState`→`renderRoom`,
  which never touches `eg_dpass`.  Paths that change the seated/bench
  count mid-round and do NOT re-derive the card: `leave_room` (self-leave,
  `index.html:3916`), `pass_member`/`decide_pass`, `seat_member`/
  `seat_pick`/draft seats, the 45s staleness sweep, and `timeout_member`
  (dead code but still an RPC).  The click-time belt (#8) guards the
  ACTION against bench 0 but neither the display nor the seated-count leg.
- **Fix direction:** derive the decide card from `roomCounts()` inside
  `renderRoom` (the puppeteer that already runs on every roster change)
  under the chosen Q3 predicate, keeping the click-time belt as the last
  line.
- Severity: **BREAKS-SHOW** — the offered verb can strand the show below
  a viable cast, violating the prime invariant.

## BAD-TV

### F4 — A target leaving mid-answer leaves the segment playing a ghost (finding A)

- **Repro (harness-confirmed):** spotlight-answer, target u_s1 leaves via
  ↩ LEAVE THE CHAIR (confirm accepted).  Server: `spotlight_target` still
  `u_s1`, phase still `spotlight`, clock ticking.  Host's client: layout
  degrades to mingle (`is-mingle`) while the pill still says
  `0:58 · SPOTLIGHT`; the question card (`eg_question`) stays up because
  `egApply` short-circuits (phase+deadline unchanged, `index.html:2900`);
  recovery only when the section clock expires (`advances` keys off the
  stale server target, `index.html:2570–2576`).
- **The guard question answered:** there is **no guard** — deliberate or
  accidental.  `updateJoinBtn` (`index.html:3966–3993`) always renders
  ↩ LEAVE THE CHAIR for a seated non-host, every phase; probes show it
  visible and hittable for both target and rival in choosing AND answer
  (390×844).  The live report "appears blocked during spotlight" matches
  no code path — the plausible culprits are transient: `beat-hold` dims
  the whole room to opacity .08 during beats (`index.html:869`), and the
  keyboard-open rail overlay (`index.html:674`).  If blocking is wanted it
  must be built (SPEC Q2); today it does not exist.
- **Per-segment consequences of a chair leaving:** choosing — clean
  (rotation reads live roster, gate 14); answer — ghost segment as above;
  open floor / deliberation — clean (seat wiped next render); deciding —
  F3.
- **Fix direction:** on the seated-target guard failing (`spotTarget`
  null while server target set), the host client collapses the segment —
  clear the target/advance, drop `eg_question`, honest pill — pending the
  Q2 policy choice.
- Severity: **BAD-TV** — up to ~30s of the show pointed at nobody.

### F6 — Camera comes up off-by-"user", rescued by a 6s watchdog (finding E)

- **Observed sequence (live client):** join completes → `local video
  track: state=off off.byUser=true` → "video never attached after 6s —
  disabling blur and retrying camera" → fallback engages → video works.
- **Root cause of `off.byUser=true` when the user touched nothing:** the
  attribution is the app's own programmatic call.  daily-js marks
  `off.byUser` for any `setLocalVideo(false)` — and the app itself makes
  that call: every non-host joins with `setLocalVideo(false)`
  (`index.html:4259`), and `syncLocalPublish` sets false whenever
  `AMHOST||amISeated()` is false (`index.html:4292–4300`).  For a SEATED
  suitor rejoining, the join path is publish-OFF-then-sync-ON — two racing
  toggles whose ON leg depends on roster state being loaded and on daily
  accepting the flip mid-join; when the ON leg loses (slow roster fetch on
  a real network, or daily still processing the OFF), the track rests at
  `off.byUser=true` and NOTHING re-checks until (a) the next
  `loadRoomState` poll happens to call `syncLocalPublish` (`index.html:
  2041`) or (b) the 6s watchdog fires.  A second contributor on host
  paths: processor blur stalls the track (known bug, the code's own
  comments `index.html:4136–4139`) — but blur is opt-in `?blur=1` and
  BLUR was not on for the observed client, so the primary path is the
  publish race.  Stale state from a previous session is ruled out for the
  singleton path: `videoLeave` destroys the call object (`index.html:
  4270–4283`), and destroy stops the local stream — no track state
  survives into the next create.  What DOES survive leave: the recovery
  bookkeeping — `CAM_TRIES`, `CAM_GAVE_UP`, `BLUR_KILLED`, and a pending
  `WATCHDOG_T` are never reset in `videoLeave` (`index.html:4088–4093`),
  so a gave-up camera in room 1 refuses recovery in room 2 (page-lifetime
  poison; the pending timer itself no-ops on `DAILY` null).
- **Why 6s + full retry is the recovery:** the join preflight never
  verifies the publish decision took — `setLocalVideo(true)` is fire-and-
  hope; the only success signal consumed anywhere is "a tile with my uid
  exists" and the only consumer is the watchdog (`index.html:4176–4198`).
  Intended vs actual lifecycle is specified in SPEC ("Camera lifecycle");
  actual inserts "publish OFF → maybe ON → wait for failure → device
  fallback" where the spec says "decide once from roster truth → verify".
- **Fix direction:** make the join preflight deterministic — one publish
  decision after roster truth, verify `local.tracks.video.state` after
  setting it (retry the setLocalVideo, not the device), keep the watchdog
  as hardware-only last resort, and reset CAM_*/BLUR/WATCHDOG state in
  `videoLeave`.
- Severity: **BAD-TV** — 6–9 seconds of dead camera on seated suitors'
  joins, on a cadence that looks random to the room.

### F7 — HER CALL can evaporate; empty-stage deciding offers verbs with no objects

- **Repro (static, resolver code):** deciding with no decision → the
  generic resolver (`index.html:2955–2960`) advances at deadline+400ms to
  round+1 spotlight — her call is silently skipped (rounds can exceed 3;
  `eg_rounds` caps its dots at 3 but `round` keeps counting).  If all
  chairs leave during deciding, the card still offers KEEP/PASS with no
  tap targets; `egDecideTap` needs a chair tap that can never come; the
  same silent advance is the only exit.
- **Root cause:** deciding has no expiry policy of its own and no
  empty-stage degrade; SPEC Q5 is genuinely open.
- **Fix direction:** pick Q5 and encode it (explicit expiry semantics +
  explicit empty-stage degrade to draft/refill or end-alone).
- Severity: **BAD-TV** (BREAKS-SHOW at the empty-stage corner, but that
  corner requires all three chairs to walk during her 60s call).

## COSMETIC

### F8 — `chair__foot` serves two masters on the target's cell

The ASKED badge and the spotlight-target caption share `.chair__foot`:
base slot hidden at top:40px (`index.html:235`), ASKED badge restyles it
bottom-left (`index.html:418–424`), and `.is-spotlight .chair.is-target
.chair__foot{display:block}` (`index.html:485`) force-shows the slot on
the target DURING his answer — so on the host's screen (the only client
with ask state, F2) the target answers with an "ASKED" badge already on
his cell, and on everyone else's the slot flashes empty.  Part of the
"still doesn't work so well" report.  Fix direction: give the spotlight
caption its own element; ASKED owns the foot exclusively (rides with F2's
branch).

### F9 — Phase pill lies while the layout degrades

Ghost-target state (F4): pill shows `M:SS · SPOTLIGHT` while the room
renders mingle (`renderRoom` effPhase downgrade, `index.html:2492–2497`
vs pill label `index.html:2352–2370`).  Fix direction: pill derives from
the same effPhase the layout uses (rides with F4's branch).

### F10 — Bench-pick window over an emptied bench

If the last bench member leaves during the 20s window, "PICK FROM THE
BENCH" sits over nobody until expiry (open Q7; `passPickOpen` checks
bench only at open, `index.html:3106–3117`).  Fix direction: close the
window early when `roomCounts().bench` hits 0 (rides with F3's branch).

### F11 — Camera-recovery poison survives the room

`CAM_GAVE_UP`/`BLUR_KILLED`/`CAM_TRIES`/pending `WATCHDOG_T` are
page-lifetime, never reset on `videoLeave` (`index.html:4088–4093`,
`4270–4283`) — documented under F6, listed separately because it bites
even when F6's race never fires (give-up in room 1 → no recovery in room
2 until a devicechange event forgives once).  Fix direction: reset the
recovery state machine in `videoLeave` (rides with F6's branch).

## Proposed branch plan

Grouped the way this week's fixes were grouped — one disease per branch,
each shipping its gate alongside the fix.  Order = severity, and F1/F2
first because every later gate wants their mechanics (reload-survival and
server-side ask truth) in place.

1. **fix/show-survives-host** — F1.  Crash recovery honors the 120s
   absence rule; a reloading host resumes her live room.
   *Gate 17-host-comeback:* host reloads mid-round → room stays live,
   host lands back in it hosting, watchers never see an ending; a truly
   stale room (aged `host_seen_at`) still gets ended.
2. **fix/ask-ledger** — F2 + F8.  `ask_question` writes a `spotlight`
   room_event (double parity); clients fold events into the (member,
   round) maps on entry and live; `chair__foot` conflict untangled.
   *Gate 18-ask-ledger:* spectator and chair clients render ASKED; host
   reload restores rotation state; the target's cell carries no ASKED
   badge during his own answer.
3. **fix/decide-truth** — F3 + F7 + F10.  Decide card derives from
   `roomCounts()` on every roster change under the Q3 predicate (owner
   picks Q3/Q5 first); explicit empty-stage degrade; pick window closes
   when the bench empties.
   *Gate 19-decide-truth:* bench/chair departures mid-deciding flip PASS
   off live; empty-stage deciding degrades explicitly; expiry follows the
   chosen Q5 policy.
4. **fix/segment-collapse** — F4 + F9.  Target departure collapses the
   answer segment (per Q2 choice); pill and layout derive from the same
   effective phase.
   *Gate 20-segment-collapse:* target leaves mid-answer → segment ends
   within one beat, question card down, pill honest, next segment on time.
5. **fix/quiet-diagnostics** — F5.  `vdbg` panel strictly behind
   `?debug=1`; translate-row states surface as show language.
   *Gate 21-quiet-diagnostics:* with errors forced (token failure, camera
   error), `#vdebug` never becomes visible without `?debug=1`; the
   show-language states appear instead; with `?debug=1` the full log does.
6. **fix/camera-preflight** — F6 + F11.  Deterministic publish decision
   after roster truth, verified track state, watchdog demoted to hardware
   last-resort, recovery state reset on leave.
   *Gate 22-camera-preflight:* seated-suitor rejoin publishes within one
   beat with no watchdog firing; budgets hold; leave resets the recovery
   state machine (give-up in room 1 doesn't poison room 2).

Open questions Q1–Q7 in SPEC.md need owner calls before branches 3 and 4;
branches 1, 2, 5, 6 are unambiguous under the spec as written.
